# Real DOM canvas WebGL integration — 2026-09-18

The public [Three fixture](../../examples/webgl-dom/main.mjs) now runs unchanged
in the actual DOM host. `new WebGLRenderer()` creates its own HTML canvas through
`document.createElementNS`, obtains WebGL2 through `getContext`, calls `setSize`,
appends the canvas to `document.body`, and draws a normal-material box on Metal.
No canvas/context injection or native test imports occur in the application.

This is an opt-in extension tested in the compiled UI runtime's integration host.
It does not yet enable WebGL presentation in the native-window player or make
`3jsn build` accept arbitrary web projects. The test executes the bundled module
against an initial document; it does not load the fixture's HTML entry page.

## Actual controls

The GPU test passes with both preserved and omitted dynamic HTML parsers. It
checks native mesh pixels, the real DOM canvas brand/parent, stable context
identity, mixed WebGPU/WebGL mode rejection, native resize dimensions, unchanged
application viewport state and fully initialized replacement storage. Repeating
a size assignment resets storage without replacing the JavaScript context.

Unsupported zero extents explicitly throw in this experimental backend. A failed
resize preserves native dimensions; a failed creation does not lock the canvas
mode. Borrowing `getContext` onto a div rejects before native context creation.
Existing WebGPU context creation/identity/mode behavior remains exercised.
Host-only probe globals are absent, and native context teardown is idempotent.

## Reproduce on the tested Metal host

Prepare the existing pinned ANGLE and DOM experiment dependencies first. From
repository root, using the existing matching V8 archive and shared build cache:

```sh
node_modules/.bin/esbuild examples/webgl-dom/main.mjs --bundle --format=iife \
  --platform=browser --outfile=.cache/native-webgl/dom.js
export CARGO_HOME="$PWD/.cache/cargo" CARGO_TARGET_DIR="$PWD/target" CARGO_INCREMENTAL=0
export RUSTY_V8_ARCHIVE="$PWD/target/release/gn_out/obj/librusty_v8.a"
export THREEJS_NATIVE_ANGLE_PACKAGE="$PWD/.cache/native-webgl/node_modules/gl"
export THREEJS_NATIVE_DOM_FIXTURE="$PWD/.cache/native-webgl/dom.js"
MTL_DEBUG_LAYER=1 cargo test --offline --locked -j2 \
  --manifest-path experiments/compiled-ui-runtime/Cargo.toml \
  --features native-webgl --test webgl_dom -- --ignored --exact webgl_dom_canvas --nocapture
```

Repeat with `--no-default-features --features native-webgl` for parser omission.
The feature and test are explicit because root source CI has no Metal/ANGLE runner.

## Remaining scope

[Native composition](../investigations/webgl-dom-composition.md) is the next
boundary. WebGL-only windows need independent host-device ownership, a GPU-only
snapshot/lease adapter and checked event ordering. The existing compositor still
expects a configured WebGPU canvas. No dummy WebGPU canvas, Deno texture disguise
or CPU frame transport has been introduced.

Zero-sized canvases, requested context-option negotiation, complete WebGL/WebIDL
behavior, context loss and resource reclamation before realm teardown remain
incomplete. Neither parser mode nor this fixture certifies a compatibility profile.
