# Browser/native overflow comparison — 2026-09-18

**Partial: 2/22 baseline cases match browser geometry and uniform interior pixels.
A rejected paint prototype reaches 16/22.** Neither establishes unchanged HTML/CSS
support. Issue [#52](https://github.com/PANDORMedia/3JSN/issues/52) remains open;
the prototype is preserved for reproducibility, not installed by preparation.

This work separates three defects that a single canvas screenshot concealed:

- Hoisted paint positions can use ancestor offsets from the previous layout.
  On the first visible case, the subject's reported rectangle starts at (176,120),
  while the baseline paints it at (120,80).
- Hoisted children can lose the overflow clips of skipped ancestors.
- Absolute/fixed layout lacks authoritative containing-block ownership; a paint
  repair cannot correct the underlying dimensions and coordinates.

The comparator verifies identical HTML/JS/case hashes, case ordering, viewport,
device scale, dimensions and recorded PNG pixel hashes. Parity allows a maximum
two-level RGBA difference in browser-uniform 3x3 neighborhoods and 0.1 CSS pixel
in geometry. Edge differences are counted separately. These finite fixtures and
tolerances are not a general CSS conformance test.

The negative-z fixture was strengthened after visual review found the body
background hid its subject. The corrected reference has 1,920 visible subject
pixels; all 22 cases were recaptured. The comparator now rejects any non-hidden
case with no visibly exercised subject. The baseline count is therefore 2/22,
superseding the earlier 3/22 count from the occluded control.

## Why the prototype was not adopted

The patch reconstructs skipped ancestors from current layout, restores rounded
padding clips and handles both z-index signs. That explains the improvement,
including the initial-frame and scale-change cases. However, review found:

- Unsupported ownership falls back silently to the old paint path; the public
  renderer API cannot report that failure to our adapter.
- The eligibility guard does not cover all skipped effects, including filter,
  clip-path, mask, isolation and containment combinations.
- Repeating ancestor clips consumes a cumulative layer budget. Exhaustion can
  omit a child silently. Traversal and path allocation also repeat per child.

Adding more special cases here would obscure the missing layout model. The
default experiment retains only the previously validated stacking-demotion patch.
The new prototype is a separate, explicitly unadopted research input.

## Required architectural work

Pinned Blitz assigns generated layout children to their immediate containers,
which Taffy uses for absolute positioning. There is no separate authoritative
absolute/fixed containing-block identity. Replacing `layout_parent` alone also
loses the original static-position anchor for auto insets.

The next design must preserve both the positioned owner and the static-position
anchor from the original formatting context. Painting, CSSOM geometry, scrolling
and hit testing must consume compatible coordinate ownership. This applies to
block, inline, flex and grid paths; duplicating their layout algorithms locally
would need an explicit maintenance decision.
This work is tracked in [#54](https://github.com/PANDORMedia/3JSN/issues/54),
a P0 child of CSS painting that blocks the complete clipping repair.

CSS explicitly allows positioned descendants to escape intermediate overflow
clips and scrolling when their containing block is outside that ancestor.
[CSS overflow specification](https://www.w3.org/TR/CSS22/visufx.html#overflow-clipping).
Containing-block establishment and transformed fixed descendants have additional
rules. [CSS positioning](https://www.w3.org/TR/css-position-3/#def-cb),
[CSS transforms](https://www.w3.org/TR/css-transforms-1/#transform-rendering).

The current suite does not exercise scrolling, text, every effect combination,
inline/flex/grid auto positioning or all platform backends. The existing DOM
adapter has no native `scrollLeft`/`scrollTop` properties; ordinary JS assignment
would create an expando and cannot count as a scrolling test. These remain gates,
alongside the original canvas clipping regression.
