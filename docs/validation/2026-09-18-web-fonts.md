# Packaged webfonts on Metal

Date: 2026-09-18. `3jsn build --bundle-web-fonts` now extends the experimental
`dom-window-v1` profile with local CSS/font resources and checked native font-face
loading. The [build contract](../web-fonts.md) defines admission, cache ownership,
bounds and unsupported features. This checkpoint preserves application source;
the player still parses HTML/CSS at runtime.

## Observed package behavior

The [public Type Lab fixture](../../fixtures/web-fonts/README.md) uses Roboto
variable weights, Noto Serif normal/italic faces, overlapping declarations,
Unicode ranges and a runtime change from Latin to Greek/Cyrillic text. The
[report](2026-09-18-web-fonts/report.json) records 25 distinct WOFF2 files and two
generated stylesheets, with 28 authored faces actually registered before layout.
No requested face remained pending. Decoded responses totalled 1,493,040 bytes;
this is not a peak-memory measurement.

An online build pinned remote bytes. A second build with network access denied
produced identical manifests, payload bytes and player bytes from that state.
Both builds retained the same before/after source digest in their
[provenance](2026-09-18-web-fonts/build-provenance.json).
The first package was relocated to a path with spaces, Unicode and `#`, and its
temporary source tree was removed. The native run used no Node on PATH, with
networking and development-source/font-cache reads denied by the
[macOS sandbox policy](2026-09-18-web-fonts/native-offline.sb). Seven explicit
denied-read controls passed. The application presented 120 Metal frames with
native device/queue identity checks and no CPU image transport between renderers.

Separate controls rejected corrupted stylesheet/font payloads, a correctly
hashed but malformed WOFF2, and a correctly hashed module that injected a new
font rule. Restoring each mutation left the package valid. The
[earlier fallback-font DOM package](2026-09-18-web-fonts/legacy-dom-regression.json)
also passed its relocation, presentation and error-control regression with this
player.

## Matching and layout evidence

Chrome 153 loaded the exact generated HTML/CSS/font assets. A shared measurement
module collected 11 widths before and after localization. All 22 native widths
passed the 0.25 CSS-pixel threshold; the largest observed difference was
0.015625 pixels. Independent controls established different family/weight
metrics, `unicode-range` fallback and later-rule precedence. The browser harness
isolates HTML text measurement; the native run separately executes Three.js.
These checks do not establish general pixel or shaping parity.

The [first integration run](2026-09-18-web-fonts/before-width-fix.json) registered
all faces and passed selection controls but failed five width comparisons. Blitz
rounded intrinsic text widths up to whole device pixels before layout. The
separate `blitz-inline-font-width.patch` removes those two premature ceilings;
paint rounding and CSSOM quantization remain unchanged. Five focused layout
tests cover fractional widths at multiple scales, ligatures, wrapping boundaries,
explicit sizing/padding and an integer control. Three fail before the repair;
all five pass afterward.

Fontique/Parley candidates carry authored ranges and CSS source order through
selection and shaping without editing font bytes. Their independent
[matcher experiment](../../experiments/web-font-matcher/README.md) passes 16 CPU
tests; its unmodified-upstream control demonstrates two expected failures.
Blitz adds checked loading/registration and cached font-rule mutation detection.
The [preparation record](2026-09-18-web-fonts/preparation.json) pins all source and
patch identities; registry sources remain untouched.

## Validation and remaining gates

[Checks and logs](2026-09-18-web-fonts/checks.json) record 119 passing Node tests
and one platform skip, 25 passing workspace Rust tests and two existing ignores,
16 passing DOM-player tests, and 15 focused Blitz font tests. Formatting,
preparation verification and scoped application Clippy pass. Real HTTP-stream
tests verify abort/deadline handling, closed responses, released cache leases,
source preservation and retry without a partial pin.

The broad Blitz library suite reports 63 passes and two failures in hover
invalidation and scroll overflow. The same failures occur without the new
inline-width repair. The isolated
[pre-webfont baseline](2026-09-18-web-fonts/pre-webfont-baseline/report.json)
reproduces the same assertions (48 passes, two failures), with unmodified
Fontique/Parley and the published dependency versions. These failures predate
this feature in the tested configuration; their root causes are not established.
This checkpoint does not claim a fully green upstream suite.
Existing dependency deprecation/dead-code warnings remain outside application
Clippy's scope.

Current admission is static, unconditional, one-URL font faces with the supported
descriptors. Conditional/dynamic font rules, source-list loading, asynchronous
font-display/FontFaceSet semantics, all Unicode shaping cases, native Windows/Linux
font delivery, general asset loading and release certification remain open.
Roboto and Noto OFL notices are explicitly included by this fixture's package
harness; automatic license discovery and the complete distribution notice
inventory are separate release gates. No downloaded font binaries, executable
or private game assets are committed here; the matcher uses original MIT fixtures.

Reproduce with the [package probe](../../scripts/probe-web-font-package.mjs):

```sh
node scripts/probe-web-font-package.mjs \
  target/debug/threejs-dom-window-probe \
  .cache/dom-canvas/blitz/examples/wasm_hello/assets/DejaVuSans.woff2 \
  artifacts/web-font-check \
  '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
```
