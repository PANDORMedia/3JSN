# V8 and Blitz: executable DOM integration evidence

Observed on 2026-09-17, macOS arm64, Rust 1.93.0. This advances
[issue #22](https://github.com/PANDORMedia/3JSN/issues/22); it does not complete the
HTML/backend selection gate. Source, commands and explicit limitations are in
[the isolated experiment](../../experiments/html-v8/README.md). Raw observations
and input hashes are in [the report](2026-09-17-html-v8.json).

## What ran

One `deno_core 0.412.0` isolate, reporting V8 `15.0.245.2-rusty`, called the public
Rust APIs of Blitz Git `9d92719b37c801b8b41c81b799a2a474db8b3936`. The independent
Cargo workspace and lockfile contain no Boa dependency. No root Cargo/runtime/
player changes or upstream source patches were required.

The [original dynamic DOM fixture](../investigations/html-dom/fixture.js) ran
without edits. Its supported observations agreed with Chrome 153.0.8010.48:

- Repeated queries preserve node object identity and expando properties.
- `innerHTML`, selectors, class mutation and text mutation observe the Rust DOM.
- A width change followed by `getBoundingClientRect` returns 120 then 240 pixels.
- `button.click()` dispatches capture, target and bubble listeners in that order.
- Removing, mutating and reinserting a node preserves its JS identity.
- Repeated `classList` access returns the same object.
- An input created by the fixture satisfies `instanceof HTMLInputElement`.

All 15 additional [behavior checks](../../experiments/html-v8/behavior.js) passed
in both the native probe and the browser. The most important case moves the target
to a different parent inside its listener, mutates text and width, and immediately
reads the new layout. The in-progress event follows its original propagation
path; the next event sees the new tree. Cancellation, once listeners, listener
removal during dispatch, passive listeners and stopped propagation also agree.
Invalid selectors, parent removal and hierarchy cycles are rejected.

These are positive results for the declared subset, not complete DOM conformance.
The original fixture still reports undefined canvas `getContext`, Worker,
WebSocket, Web Audio and MutationObserver. The prototype's input subclass proves
only the tested prototype relation, not HTML input-element implementation.

## Ownership findings

The Rust `BaseDocument` is authoritative. JS holds wrappers and listener state,
not duplicate node relationships. Synchronous native operations return before
calling listeners. A reentrant listener therefore obtains a fresh document borrow
rather than calling into JS while Rust still holds a mutable reference.

Blitz's public APIs suffice for this subset. One important adaptation is required:
`DocumentMutator::set_inner_html` drops old child nodes, whereas browser script
may keep those nodes alive through references. The probe instead detaches children
with `remove_node`, then calls
`DocumentHtmlParser::parse_inner_html_into_mutator`. A retained old child remains
usable and can be reinserted. This does not solve garbage collection: the proof
retains wrappers/detached nodes until the entire document is destroyed.

Node identifiers are passed as decimal strings, preserving all 64 bits of the
upstream versioned handle. No native pointer is exposed to script. All bridge
operations validate that the node still exists before accessing it.

## Timing and validation limits

The host supplied two manual RAF timestamps, 100 and 116.6666666667 milliseconds.
The callbacks observed those values. Browser timestamps came from headless browser
scheduling and are intentionally different. This validates a callback seam only;
it is not native display pacing, a latency result, or a performance comparison.

The separate probe compiled and ran against its pinned lockfile. Browser and
native checks compare behavior of identical fixture scripts; no expected DOM
result was substituted for a failed native call. Capture objects record unsupported
features alongside the passing subset.

No GPU drawing, HTML painting, Three.js scene, native input, forms/default actions,
IME, accessibility, full CSS visual comparison, JS-node garbage collection or
Servo comparison ran in this probe. Page parsing and script-loading lifecycle are
also outside its scope. The local player is not yet connected to this DOM adapter.

The next integration gate is one real canvas and HTML layers using a compatible
shared GPU device, followed by native input/default-action and resource-lifetime
validation. Preserve the source-backed limitations from the
[initial HTML investigation](../investigations/html-dom.md) until those tests pass.
