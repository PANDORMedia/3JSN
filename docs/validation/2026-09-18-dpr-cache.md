# DPR cache invalidation

The positioned research candidate now refreshes device-space transform and
overflow caches when viewport scale changes. Three CPU regressions move an
unchanged document through DPR **1→2→2→1**: the previous candidate fails all three;
the narrow repair passes all three. This is not live-window or GPU DPI validation.

When physical viewport size and DPR grow together, the CSS viewport can stay
unchanged. The previous `SCALE` branch invalidated inline text layouts only.
Box-only transforms and overflow remained clean, so the existing resolve pass
reused their old device-pixel values. The repair marks every in-document node
`RECALCULATE_OVERFLOW`, preserving the existing text invalidation and using the
normal post-layout recomputation. It adds no forced recascade, paint-side scale
correction or dependency. The extra traversal runs only on scale changes; its
cost has not been benchmarked.

## Evidence

| Identical test source | Previous candidate | Repaired candidate |
| --- | --- | --- |
| Pixel/percentage translations, ancestor overflow and paint bounds | Fail: `.375` instead of `.75` at DPR2 | Pass |

| Rotation/scaling around a nonzero transform origin | Fail: approximately `60` instead of `120` | Pass |

The initial DPR1 assertions pass before the baseline failures. The repaired run
also checks unchanged linear transform coefficients, nonzero physical paint
offset, balanced scene layers, identical repeated-DPR2 commands and identical
restored-DPR1 commands. No expectations or tolerances changed between runs.

its new SHA pin and accepts exact restoration. Syntax, formatting and receipt

of the shared window experiment's lockfile; no unlocked test run was substituted.

## Reproduce and remaining gates

After [preparing the candidate](../../experiments/dom-canvas/POSITIONED.md):

```sh
CARGO_HOME="$PWD/.cache/cargo" CARGO_TARGET_DIR="$PWD/target" \
  cargo test --offline --locked -j2 \
  --manifest-path .cache/positioned-candidate/probe/Cargo.toml \
  --test dpr-transition
```

These tests record real paint commands without a GPU. Physical monitor changes,
GPU pixels/presentation, input alignment across DPR transitions, text, anonymous
and pseudo boxes, subdocuments and zoom still need integration evidence.
Transformed DOM queries, scrolling/clip semantics and general browser
compatibility are separate work; none is claimed fixed by this cache repair.
