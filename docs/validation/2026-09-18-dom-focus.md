# Native DOM focus and keyboard routing — 2026-09-18

This checkpoint adds bounded element focus to the shared live native document.
The authoritative Rust tree owns the focused node; JavaScript sequences events
only after native document borrows have been released. The final checkpoint
matches 44 bounded browser semantic cases in both parser
modes, in CPU and native-window runs, and presents 120 Metal frames per mode.
It retains explicit event-interface differences and does not establish complete
browser focus or input support.

## Implemented boundary

`document.activeElement`, element `focus()`/`blur()` and `tabIndex` use native
eligibility and document order. Positive tabindex candidates precede natural
order. Eligibility accounts for connection, disabled controls/fieldsets,
hidden inputs, inert ancestry and resolved display/visibility. HTML attribute
names are ASCII-case-insensitive; foreign attribute names retain their case.
Tree, stylesheet and focus-state changes also schedule eligibility checks.
Losing eligibility normally schedules a later-task fixup; `hidden`
clears focus immediately. This timing is part of the bounded implementation.

Focus transitions emit `blur`, `focusout`, `focus` and `focusin` with
`relatedTarget`. Reentrant handlers can supersede a pending transition. Mutation
preflight validates removal/reparenting before blur, then the mutation validates
again after callbacks. Invalid removals and cycles preserve focus; removing a
focused subtree blurs while still attached. Replacing the focused element's own
text preserves focus; replacing an ancestor's children clears it. Moving an
already focused node also runs removal focus steps for no-op insertion cases.

The window adapter resolves a fresh active target for every keydown and keyup,
so a focus change in keydown retargets keyup. Events bubble through Document to
Window. A small checked build-time patch to pinned Deno event source adds that
parent edge, preserves the original target and excludes Document `load` events.
It does not rewrite the dependency registry or replace Deno EventTarget.

Uncanceled primary mousedown resolves focus eligibility after handlers. An
uncanceled Tab keydown navigates candidates; Shift reverses direction, while
Control/Alt/Meta combinations do not trigger this default. Cycling at the native
window boundary is an explicit host policy: the Chrome navigation oracle includes
a body step and a known negative-tabindex boundary difference. An element with
its own `display: contents` is ineligible; a contents ancestor does not make its
otherwise eligible descendants ineligible.
OS window focus remains distinct from element focus. Physical key code, repeat
and aggregate modifier fields travel with input records; changes in modifiers
prevent adjacent mouse moves from coalescing.

## Reproduction

Build and retain both debug executables using the
[compiled runtime instructions](../../experiments/compiled-ui-runtime/README.md),
including the verified dependency preparation. Then run on macOS arm64:

```sh
node scripts/probe-dom-focus.mjs \
  --preserved /path/to/preserved-runtime \
  --restricted /path/to/restricted-runtime \
  --font /path/to/DejaVuSans.woff2 \
  --browser '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
  --out artifacts/dom-focus-new-run
```

The original fixture remains unchanged. A disclosed generated wrapper adds a
canvas for the current build profile; this is a harness adapter, not proof of
unchanged arbitrary project admission. Both relocated packages run with network
and development-source reads denied. `--cpu-only` omits window validation.
The [archive manifest](2026-09-18-dom-focus/archive-identities.json) maps original
receipts and logs to their archived files; paths inside receipts describe the
original local captures. [Source identities](2026-09-18-dom-focus/source-identities.json)
cover the changed implementation and executable fixture sources.

## Remaining limits

Events are ordinary **untrusted `Event` objects** with readonly fields, not
`FocusEvent`, `KeyboardEvent` or `MouseEvent` instances. This does not extend the
standalone player's separate trusted-event contract. Key location, full modifier
side reconciliation, IME/composition, editing/selection, forms/default activation,
full HTML control reflection, focus-visible modality, accessibility and
focus-driven scrolling are not
implemented by this checkpoint. Shadow roots, embedded documents and browser
chrome focus transfer are outside this model. Other platforms and physical
keyboard/pointer behavior require hardware evidence. No performance, complete
DOM parity, arbitrary React compatibility or unchanged arbitrary application
compatibility is inferred.

## Invalid receiver correction after daily review

The [PR review](https://github.com/PANDORMedia/3JSN/pull/62#pullrequestreview-5249906508)
identified that borrowing `Element.prototype.innerHTML` onto a Text or Document
could reach the parser without an Element guard when no element was focused.
The new failing regression reproduced that path before the correction. Mutation
now validates the receiver before detaching any children or calling the parser.
Geometry requires an Element; selector reads retain valid Document and Element
scopes and reject Text receivers.

A new runnable `dom_receivers` integration target exercises actual V8 bindings and
shared native DOM operations with the parser preserved and omitted. Both modes
pass 24 tests; strict scoped Clippy passes for both. Controls verify unchanged
root/subtree identity after rejected borrowed setters and positive query, geometry
and real parsing behavior. [Receipt and reproduction commands](2026-09-18-dom-focus/receiver-review/receipt.json)
and raw logs retain the pre-fix failure. This is CPU/runtime-boundary evidence;
no new GPU, window, device-input or platform support claim is made.
