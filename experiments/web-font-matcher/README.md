# Web-font matching candidate

This isolated CPU probe extends pinned Fontique/Parley 0.11.1 for CSS face
registrations. It does not replace shaping or modify font source blobs. The DOM
host must use a document-local collection and supply validated CSS descriptors
in stylesheet order after its stylesheet snapshot is complete.

Prepare and verify without network access:

```sh
CARGO_HOME="$PWD/.cache/cargo" node experiments/dom-canvas/prepare-fonts.mjs
CARGO_HOME="$PWD/.cache/cargo" node experiments/dom-canvas/prepare-fonts.mjs --check
CARGO_HOME="$PWD/.cache/cargo" node experiments/web-font-matcher/check-upstream.mjs
CARGO_HOME="$PWD/.cache/cargo" CARGO_BUILD_JOBS=2 \
  CARGO_TARGET_DIR="$PWD/.cache/web-fonts/target" \
  cargo test --offline --locked --manifest-path experiments/web-font-matcher/Cargo.toml
```

`check-upstream.mjs` verifies **two expected failures** on unmodified Fontique:
only the first equal-attribute coverage variant is queried, and scalar weight700
metadata suppresses the variable font's required `wght`700 coordinate. It fails
if those tests unexpectedly pass or fail to compile. The candidate passes both
and 14 additional public-API tests. Strict Clippy passes for the test target;
Parley's existing ICU `to_icu4c_value` deprecation warning remains upstream.

The preparer pins the complete source file set/content, both patch bytes and
complete patched output. Cargo installation receipts are excluded from the tree
hash. Fresh/repeated preparation, verification, changed source, extra source and
source-symlink rejection were checked in a disposable directory. Registry source
is read-only; prepared copies live under `.cache/web-fonts/{fontique,parley}`.

## Registration contract

```rust,ignore
let descriptor = fontique::WebFontFace::new(
    css_source_order,
    &[(0x0000, 0x00ff), (0x0131, 0x0131)],
    (100.0, 900.0), // inclusive weight
    (100.0, 100.0), // width percentage
    fontique::WebFontStyle::Normal,
)?;
collection.register_fonts(blob, Some(fontique::FontInfoOverride {
    family_name: Some("Example"),
    web_font: Some(&descriptor),
    ..Default::default()
}));
```

`WebFontStyle::Italic` and `Oblique { min, max }` represent CSS style descriptors;
oblique bounds are CSS degrees. Omitted descriptors must become CSS defaults
(weight400, width100, Normal, Unicode0..0x10ffff). The descriptor is owned and
clonable; registration retains it. Every distinct rule in one family needs a
unique `source_order`. Higher order wins overlaps independently of load order.
Raw `FontInfo` scalar getters still describe intrinsic/overridden metadata;
`FontInfo::web_font()` exposes the authoritative CSS ranges.

The query considers every face in the winning descriptor bucket, shadows
installed faces with the same family name, and preserves caller family order.
Unicode eligibility travels through `FontInfo`, `QueryFont`, its effective cmap
and a small Parley adapter using HarfRust0.12's public `FontFuncs`. The latter is
necessary: Parley can retain a partially covering last-resort face and then
shape the original blob. Filtering only the selection cmap would let excluded
glyphs reappear. Nominal and variation-selector mapping both restrict the base
Unicode scalar before delegating to HarfRust's builtin mapping and metrics.
Existing GSUB/GPOS data, glyph identities and font bytes remain intact.

Range matching reuses Fontique's CSS directional priorities after projecting
each descriptor interval onto the request. High-level variable coordinates are
clamped to descriptor and native axis ranges; explicit element variation
settings retain their later precedence. CSS positive oblique angles become
negative OpenType `slnt` coordinates. Non-web scalar weight synthesis includes
the upstream axis-default correction.

## Evidence and limits

Tests inspect queried and shaped blob identities, glyph IDs, widths, normalized
variable coordinates and source bytes. They cover three same-family subsets,
overlap precedence under reversed completion, next-family fallback, excluded
last-resort/variation-selector glyphs, a combining cluster, a retained `fi`
ligature, weight/width/oblique interval matching, exact descriptor overrides and
explicit variation precedence. Test-only comparison accommodates one F2Dot14
unit of normalization rounding and less than0.0001 percentage point from
FontWidth's f32 ratio conversion.

The original fonts in `fixtures/` are generated by the adjacent standard-library
Python script and are covered by the repository's MIT license. Their glyphs are
simple rectangles, with an original `fi` GSUB ligature and A+FE0F variation
mapping. The variable file has four `fvar` axes but deliberately no interpolated
outlines: normalized-coordinate tests establish coordinate selection, not
variable-outline rendering or browser pixel parity.

This is a bounded candidate, not full CSS Fonts conformance. The [integrated package checkpoint](../../docs/validation/2026-09-18-web-fonts.md)
compares actual provider-font widths with Chrome on one Mac; this isolated probe
does not perform that comparison. Complex-script/normalization
fallback still uses Parley's existing cluster algorithm; these tests do not
establish all Unicode fallback behavior. Descriptor `font-variation-settings`,
feature/metric overrides, optical sizing, source-list loading, CSS Font Loading
API and dynamic removal/reordering are not implemented here. In particular,
existing scalar `unregister_font` is not a per-web-face removal API. A host must
not silently treat those capabilities as supported.

Upstream basis: [Parley #663](https://github.com/linebender/parley/pull/663)
(`758731a39dfa5870550c8e3531e74a4246f9e658`, coverage-variant query expansion) and
[#723](https://github.com/linebender/parley/pull/723)
(`6a9483be529f12996cd847f94b5c62a61b49a205`, variable weight default). Both are
adapted to pinned revision `eea3503dd6cf17130cbb07348e0ff2c918300e94`.

The descriptor model follows [CSS Fonts4](https://www.w3.org/TR/css-fonts-4/).
The shaping restriction follows the same placement as Chromium's
[HarfBuzzFace glyph callbacks](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/platform/fonts/shaping/harfbuzz_face.cc).
No HarfRust patch or font-byte subsetting tool is used.
